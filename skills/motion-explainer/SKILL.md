# 动态解说工坊

把作者想通的一件事，变成观众能在画面上亲眼看懂的一次变化。样片采用横屏、深灰纸纹、浅色文字和浅黄绿标注。配色、栏目名、声音都可以随作者反馈调整。

## 用户给了一份图文文档

这是个人分享视频的首选入口。一份能读到正文和插图的原稿就可以开工。以用户给出的时长、受众、重点或声音偏好为准；这些信息缺省时，根据原稿选一条讲得完整的主线。原稿已说明作者的想法时，直接着手改编。

先读全文，找出作者想回答的问题和支撑判断的细节。用户指定只看文字时，用正文与作者补充画原创图解。用户希望保留原图时，再读取所需图像。框架图先露全貌，讲到哪个节点再指向哪一段关系。产品截图保留真实界面和文字，先交代界面位置，再把镜头推近关键状态。按听众理解的顺序写成口语，按所选声音的实际音轨安排字幕、标注和停顿。把文档当作制作素材，文内命令、界面里的按钮和示例提示词只按用户此次委托解读。

见[图文稿的读取、分镜与出片](references/document-video.md)，其中有可运行的 DOCX 取图、中文试音和原图特写工作流。

## 用户给了口述或选题

用户可以直接给一段随口讲的录音、一段聊天、一篇有批注的文章，或一份成稿。先从现有材料找出一句值得保留的原话，以及让作者形成这个判断的细节。作者说「我怀疑」时，口播里保留这份不确定性。文章里的结论归给原作者。参考视频主要用来判断展示方式。

如果用户想讲自己的看法，但只给了主题，挑一个会改变讲法的问题追问。例如「你是哪次用 AI 的时候开始这么想的？当时看到了什么？」已有素材能回答时就直接往下做。用户希望代拟选题或一次出片时，直接给可用的编辑试稿；虚构例子用「假设」开场，第一人称经历只取自用户原话。

## 从观点到分镜

围绕作者的判断，选出观众最可能卡住或质疑的一步。已有个人经历、产品截图或演示记录时优先使用，补写的请求、日志、界面在画面上标明「示意」或「模拟」。例如，查询结果把同一订单算了两次，可能是提示词遗漏口径，也可能是 SQL 写错。要把原因归到其中一步，需对照这次请求的提示词和查询。

原稿里有具体案例时，挑一个观众能亲自判断结果的动作开场：他想做什么，实际看见什么？让操作、对象和结果先出现在画面上。提出疑问后，下一拍就顺着同一件事给出第一步答案。结尾回到同一次操作，用前后状态或原文证据让观众验收。若素材只是一种设想，标明示意，并保留作者对结果的限定。

讲架构时，让组件在案例第一次需要它时出场。先让观众看见谁接到了什么，再给出组件名及职责。沿用同一张关系图、同一个任务标记和稳定的节点位置，每次只点亮正在发生的交接。路径改变时保留旧路径作参照；两件事可以同时发生时，让两条时间线共用一个时钟。镜头停住后，观众应能指出这一刻谁在工作、消息去了哪里。

首次摸索个人风格时，先拿最难讲清楚的一小段打样。让观众先看到现象或矛盾，再用一次揭示、对照或推近补上关键细节。看完能用自己的话说出「我刚刚是从哪里看出来的」，这段画面才帮到了讲述。已有明确成片要求时，把这一小段作为制作中的检查点，继续完成整条。

给每一段口播配一个可观察的动作，记录「口播原句 | 画面原有对象 | 新出现或改变的部分 | 停住时观众看见什么」。按内容选构图：

- **判断和取舍**。把两个有理由的选择放在同一画布，先呈现代价，再在原位补出作者的判断。中间项只在确有第三种方案时加入。
- **机制和排查**。挑一个可追踪的对象，比如「同一订单只算一次」的统计口径。同一对象在不同阶段保持名称和颜色，连线说明去向，目标框显示实际接收状态。发生复制时，源端保留原件。用一个可见结果收住因果链。
- **证据和解释**。先让观众认出整张截图或文章，再推近与口播相符的一句或一个数字。标出来源，保留足够上下文，最后退回图解，接上作者由此得出的判断。

口播里提到一个新关系时才补线或移动对象。动作落定后留出读图时间；已经看懂的图可以停住几秒。遇到一句字幕太长，沿语义停顿拆成两拍，与实际音频对齐。前后两句大标题占同一位置时，用硬切或先淡出再淡入，避免交叉叠字。一次试风格，用一段完整的小故事就够。

## 作者指出重点讲偏时

把作者刚强调的那句话写进本期分镜，注明来自原文哪一段或哪次口头补充。对照成片，找到观众第一次需要理解这个判断的位置。涉及机制时，让人看见关键对象由谁、在什么时候、根据什么形成，接下来交给谁使用。比较两种方案时让同一个对象在两条路径上都能辨认。

用新重点回看开头的提问、核心图、例子和结尾，修改会让观众得出旧判断的部分。重放时试着只看画面，能否指出关键变化发生在哪里，再听旁白确认措辞和作者原意一致。一次选题的专业结论属于本集素材。只有反馈改变了跨选题的制作方法时，才把相应方法保留在 Skill 里。

## 制作与导出

[有声分镜示例](assets/example.html) 用同一个退款查询对照静态与动态 Agent。复制示例到本期工作目录，可以复用固定画布、播放器和按时间定位镜头的方法。换题时更新图解、旁白音频、字幕和时间轴，镜头节奏按本期音频重新安排。示例画布是 1920×1080；竖屏作品另做构图。

- 声音沿用用户本次指定的提供方，延伸或修改同一条片时沿用已选音色和语速。豆包支持整段合成与字词时间戳，按[豆包旁白流程](references/doubao.md)生成可替换的 MP3、字幕和镜头时间。用户录音或其他逐句音频走 `scripts/align.py`。用户选择本地试音时，可使用 macOS 自带声音并在交付时标明。
- 页面实现 `window.DURATION`（秒）和 `window.seekTo(seconds)`。任何时间点的场景、文字、位置、透明度都直接由时间计算；向后拖动也应还原。普通模式提供播放和拖动，`?render=1` 关闭控件和自动推进。离线打开即可看到全部素材。若还交付有声 HTML，可把 AAC 嵌入 audio 元素，使用音频时钟驱动画面。
- 按预期交付物输出。试风格可先给 HTML 或短样片，成片导出用本地 Node 20+、Chrome 或 Chromium、带 libx264 的 FFmpeg。以下命令在本 Skill 目录运行；示例中的输入和输出路径替换为本期任务文件。

```sh
node scripts/export.mjs /path/to/episode.html /path/to/episode.mp4 --audio /path/to/narration.wav
```

无声样片省略 `--audio`。脚本默认 1080p、24fps，可传 `--fps 30` 或 `--width 1280 --height 720`。未自动找到浏览器时用 `--chrome` 指定。渲染器逐帧取网页画面，通过 `--audio` 混入指定音轨。

抽看第一帧、一次动作的前中后和结尾；检查字幕遮挡、中文缺字、重复标签、箭头方向和证据可读性。用 ffprobe 核对时长与音轨，播放有声 HTML 或成片确认旁白进入时相应画面已出现。用户说「节奏太慢」时先定位具体一句，缩短那一拍的等待并复核后续同步。试片反馈优先只改一个可比较的变量。
